## Addendum 2 (2026-09-08): fix de hotkeys dirigido por QA real del propietario

El propietario reportó que el dictado no arrancaba con Option (ninguno de los dos lados). Causa raíz verificada contra el SDK de Apple (`Events.h`): `HotKeyManager` usaba keycodes incorrectos — 58 (que ES `kVK_Option`, Option **izquierda**) etiquetado como "Right Option", y 54 (que ES `kVK_RightCommand`, ⌘ derecha) etiquetado como "Right Control". Fix iterado en 3 pasos con QA real: (1) dictado acepta Option de ambos lados (58/61); (2) el propietario aclaró su hardware — **MacBook Pro M4 14" no tiene Control derecho** (ningún laptop Mac lo tiene: fila inferior = fn ⌃ ⌥ ⌘ espacio ⌘ ⌥), así que limpieza se rebindeó a **⌘ derecha (0x36)**, presente en el 100% de Macs e inerte sola; (3) dos hardenings del mismo hallazgo: el flag verificado es `.maskCommand` (`.maskControl` nunca se encendería con ⌘ derecha — bug que habría dejado la limpieza muerta), la grabación solo termina cuando NINGUNA hotkey sigue presionada (cruce Option→⌘Ⓡ ya no corta el dictado), y las hotkeys solo disparan como modificador desnudo (⌥/⌘ ya combinadas con ⌃⇧ = atajo real, no se secuestra). Copy actualizado en PopoverView, SettingsView, README (EN/ES) y landing. Fuera de la lista de V01 — registrado por transparencia, dirigido por bug report del propietario. Build limpio, smoke v01 14/14, app reempaquetada y relanzada (PID verificado contra mtime del binario). Working tree digest final: `working-tree:600f65c9daac381e53a95e22e86b9a001aab347d2d1854e451a00f65649e7305`.

## Addendum 3 (2026-09-08): causa raíz de "permisos que se pierden entre builds"

El propietario reportó que los permisos otorgados parecían no aplicar tras reempaquetar. Verificación: `Permissions.swift` lee los tres permisos en vivo (sin caché) — el código de Voza está bien. Causa raíz: `build.sh` firmaba **ad-hoc** (`--sign -`), cuya firma cambia en cada build; TCC liga las concesiones a la firma+bundle-id, así que cada reempaquetado anulaba los grants silenciosamente (tccutil reset All com.jerotherey.voza ejecutado para limpiar el estado viejo). Fix duradero: identidad self-signed estable "voza-dev" creada en el login keychain (trust de usuario vía `security add-trusted-cert -r trustRoot -p codeSign`, el intento admin fue denegado por no permitir interacción); build.sh ahora firma con esa identidad y cae a ad-hoc con WARN si no existe. A partir de ahora los grants sobreviven rebuilds. build.sh tocado fuera de la lista de V01 — registrado por transparencia.
